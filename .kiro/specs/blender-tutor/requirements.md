# Requirements Document: Blender Tutor

Lead: Person C. Reviewers: Person A (contract), Person B (demo scenario). Person B writes the profile content (task 9).

## Introduction

The Blender tutor is the first application built on Wysp. It is a Blender 5.2 LTS extension that implements the adapter contract at the **native** integration level through the Python API (`bpy`), plus a pedagogical profile about objects and the modifier stack. It must let Wysp explain an object and its modifiers from the real scene, guide or perform the addition of a modifier with permission, and verify the result in the scene.

## Glossary

- **Extension**: a Blender 5.x add-on packaged with `blender_manifest.toml`.
- **Main thread**: Blender's UI thread, the only thread allowed to use `bpy`.
- **Pump**: a `bpy.app.timers` callback that runs queued requests on the main thread.
- **Compensation**: the inverse operation recorded to undo a Wysp action.
- **Demo scene**: "Pumpkin Patch", generated by `apps/blender-tutor/demo/build_scene.py`.

## Requirements

### Requirement 1: Installation and connection

**User Story:** As a Blender user, I want to install Wysp like any extension and connect it to the local Core in one click.

#### Acceptance Criteria

1. THE extension SHALL install from a zip in Blender 5.2 LTS, declare the `network` and `files` permissions with reasons, and bundle its pure-Python dependencies as wheels.
2. THE extension SHALL add a "Wysp" tab in the 3D Viewport sidebar showing the connection state, a Connect/Disconnect button and the Core address.
3. WHEN the user clicks Connect, THE extension SHALL read the pairing token from `~/.wysp/token`, connect to the Core and send `wysp.hello` with its manifest.
4. WHEN the Core is unreachable, THE extension SHALL retry with backoff up to 10 s between attempts and show the state, without freezing Blender's interface.
5. WHEN the extension is disabled, THE extension SHALL close the connection and remove every handler, timer and draw callback it registered.

### Requirement 2: Main-thread safety

**User Story:** As a Blender user, I want Wysp to never crash or freeze Blender.

#### Acceptance Criteria

1. THE extension SHALL access `bpy` only from the main thread; the network thread SHALL only enqueue requests and send responses.
2. THE pump SHALL run every 50 ms and process requests for at most 20 ms per tick.
3. IF Blender is in a modal state that prevents an action (for example a running modal operator), THEN THE extension SHALL return `-32017 BUSY`.

### Requirement 3: Observation and context

**User Story:** As the Core, I want the scene as entities, so that Wysp can explain the real objects and modifiers.

#### Acceptance Criteria

1. THE adapter SHALL expose entities of kinds `scene`, `collection`, `object`, `modifier` and `material` with refs `blender://scene/<name>`, `blender://collection/<name>`, `blender://object/<name>`, `blender://object/<name>/modifier/<name>` and `blender://material/<name>`.
2. Each modifier entity SHALL have its object as parent and props `type`, `index` (position in the stack), `show_viewport`, `show_render`, and its editable RNA properties of simple types (boolean, integer, float, enum, string), at most 30, with float values rounded to 4 decimals.
3. THE adapter SHALL report the active object and the selected objects as `focus`, and links `uses_material` (object to material) and `references` (modifier to referenced object).
4. THE context SHALL summarise the scene (object count, active object, its modifier stack) and report the mode, the active object, the selection count and the current frame as facts.

### Requirement 4: Actions

**User Story:** As a learner, I want the tutor to act on my scene only through safe, reversible actions that I approve.

#### Acceptance Criteria

1. THE adapter SHALL provide the actions `select_object` (ui_state), `show_properties_tab` (ui_state), `add_modifier`, `remove_modifier`, `set_modifier_property`, `move_modifier`, `toggle_modifier_visibility`, `assign_material` (reversible) and `apply_modifier` (irreversible).
2. Each action SHALL declare postconditions and, for user-performable actions, a `guide.ui_path` describing where to click in Blender's interface.
3. Reversible actions SHALL return an undo token whose undo restores the state digest, and SHALL push a native undo step so that Ctrl+Z also reverts them.
4. THE adapter SHALL use the data API rather than operators where the data API allows it.
5. `apply_modifier` SHALL support `dry_run` and return a preview with the vertex count before and after.

### Requirement 5: Events

**User Story:** As a learner, I want the tutor to see what I change in Blender.

#### Acceptance Criteria

1. WHEN the scene changes, THE adapter SHALL send `event.state_changed` with the changed refs, at most once per 250 ms.
2. WHEN the active object or the selection changes, THE adapter SHALL send `event.selection_changed`.
3. WHEN the user adds, removes or reorders a modifier, THE adapter SHALL send `event.user_action` with kind `modifier_added`, `modifier_removed` or `modifier_moved`.
4. THE adapter SHALL tag changes caused by Wysp actions or undos with `origin: wysp` and other changes with `origin: user`.
5. WHEN a new file is loaded, THE adapter SHALL keep its subscriptions and send a full `event.state_changed`.

### Requirement 6: Highlight

**User Story:** As a learner, I want to see which object or modifier the tutor is talking about.

#### Acceptance Criteria

1. WHEN the Core asks to highlight an object, THE adapter SHALL draw a pulsing outline of its bounding box in the 3D viewport for the requested duration.
2. WHEN the Core asks to highlight a modifier, THE adapter SHALL switch the Properties editor to the Modifiers tab and outline the object.
3. Highlighting SHALL NOT change scene data.

### Requirement 7: Headless mode and contract

**User Story:** As a developer, I want to run the contract kit against Blender without opening its interface.

#### Acceptance Criteria

1. THE script `demo/run_adapter.py` SHALL run the adapter in background mode (`blender -b`) with a manual pump loop on the main thread.
2. In background mode, THE adapter SHALL return `-32010 NOT_SUPPORTED` for `adapter.highlight`.
3. THE adapter SHALL pass the contract kit with `apps/blender-tutor/contract.fixture.yaml`.

### Requirement 8: Profile and demo scene

**User Story:** As a learner, I want a short course on objects and modifiers that uses my scene.

#### Acceptance Criteria

1. THE profile SHALL define the skills `scene_navigation`, `modifier_stack`, `subdivision_surface` and `bevel_modifier`, a glossary of at least 12 concepts with links to the Blender manual, and the lessons L01 scene tour, L02 modifier stack and L03 bevel.
2. Lesson L03 SHALL include the exercise "give the bevel 3 segments", verified by a predicate on the observation.
3. THE script `demo/build_scene.py` SHALL generate the "Pumpkin Patch" scene (pumpkin with Subdivision Surface and Solidify, candle without modifiers, lid, ground, light, camera) reproducibly.
